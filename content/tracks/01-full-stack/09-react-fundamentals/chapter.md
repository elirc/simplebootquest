React's core idea fits in one line: **UI = f(state)**. You describe what the screen should look like for the current data, and React works out how to update the DOM.

> The React quests run in a lightweight JSX runtime, so tests can inspect what your components render. Hooks like `useState` need the real React, which you'll use in the chapter project. For practice, state logic is written as pure **reducers**, which is exactly what `useReducer` uses.
